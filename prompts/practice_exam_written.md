## Written (extended-answer) engineering problems
(Felder & Brent on engineering tests; mark-scheme practice of method marks with follow-through.)

- Test application and analysis, not recall: each problem asks the student to model a situation, choose
  the method, compute, and judge the result. One part per problem asks for interpretation (is it
  reasonable, which design is better, what limits it).
- If no count is given: mix ~30% short conceptual parts, ~50% multi-step calculation, ~20%
  design/analysis or derivation, with marks on every part.
- Make parts independent where you can. Where a later part needs an earlier result, give a fallback
  ("if you could not find Z_in, use Z_in = 62 + j18 ohm"), so one early slip doesn't cost the whole
  question.
- State every given value with units, and the assumptions a real exam would state (lossless, far field,
  free space, matched). Ask for a specific unit and precision where the real exam does (e.g. "to 2
  decimal places").
- No unfamiliar twists the lectures never prepared for. Difficulty comes from combining taught ideas, not
  from tricks or heavy arithmetic. Keep the arithmetic calculator-sized.
- Engineering exams usually run too long. Size each part at the paper's pace per mark; if your own clean
  solution would take more than about a third of the time allowed for that part, cut it down.
- Mark scheme: method marks for each key step plus an answer mark, so a correct method with a numerical
  slip still earns most of the marks (follow-through).
